Virtual functions

Virtual functions are declared (and possibly defined) in a base class, and can be overridden by derived classes. This approach declares an interface at the base level, but delegates the implementation of the interface to the derived classes.

Virtual functions can be defined by derived classes, but this is not required. However, if we mark the virtual function with =0 in the base class, then the function becomes a pure virtual function. This means that the base class declares but does not define the function. It has the side effect of making its class abstract meaning the class cannot be instantiated. A derived class must define the function, or else the derived class will be abstract.

We don't know how a generic animal talks. So we declare a function talk as a virtual function. =0 means we're never going to create an object of type Animal. We're simply creating an interface such that other classes that inherit from this base class will have to implement the talk function.

Example


    #include 

    class Animal {
    public:
      // Virtual function enables runtime polymorphism
      virtual void make_sound() {
        std::cout << "Generic animal sound\n";
      }
    };

    class Dog : public Animal {
    public:
      void make_sound() override {
        std::cout << "Woof!\n";
      }
    };

    class Cat : public Animal {
    public:
      void make_sound() override {
        std::cout << "Meow\n";
      }
    };
If you use a base class pointer to point to a derived object, virtual functions ensure the correct behavior happens: 

    void play_sound(Animal *animal) {
      // The program decides at RUNTIME whether to bark or meow
      animal->make_sound();
    }

    int main() {
      Dog my_dog;
      Cat my_cat;

      play_sound(&my_dog); // Outputs: Woof!
      play_sound(&my_cat); // Outputs: Meow!
    }
