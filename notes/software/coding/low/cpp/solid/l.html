Liskov substitution

Overview

Subtypes must be substitutable for their base types without altering the correctness of the program. This states that a parent class (say when passed as an argument to a function) should be substitutable by any of its derived classes. This principle ensures that inheritance is used correctly.

Example

[code]

testArea() is written against the Rectangle interface and relies on a reasonable assumption: setting width and height independently gives you width * height. That's an implicit contract of Rectangle. Square compiles fine, inherits fine, and "is-a" Rectangle in a mathematical sense — but it silently breaks that contract, because setting one dimension secretly changes the other. The function has no way to know this, and the bug only shows up at runtime with wrong output, not a compile error. That's precisely what LSP says: subtypes must be substitutable for their base type without altering the correctness of the program. If a subclass changes behavior in a way that violates assumptions callers reasonably make about the base class, it violates LSP — even if it satisfies "is-a" intuition and the type system. The fix is usually to stop modeling this with inheritance at all (e.g., have both Rectangle and Square implement a common Shape interface with just getArea(), without one inheriting from the other).
