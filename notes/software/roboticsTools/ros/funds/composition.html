Composition

Overview

Running multiple nodes as components within a single process (rather than separate processes) to reduce overhead — especially important for intraprocess communication to avoid serialization costs on things like image/pointcloud data.

Mental model: A node can be written as its own separate program (own process, own PID). Composition loads several node classes into a single process instead — like merging five employees into one shared office instead of five separate buildings connecting by mail. Less overhead, faster communication between them.

Diagonostics


    ros2 launch ros2_fundamentals_cpp composition_launch.py
    ps aux | grep component_container   # only ONE process, not five
    ros2 component list                 # but ROS 2 still sees talker/listener/add_two_ints_server as separate nodes inside it
    ros2 topic echo /chatter            # still works exactly the same from the outside
That last point is the whole lesson of composition: the interface (topics/services/actions) looks identical whether a node runs standalone or composed — composition is a deployment/performance choice, not something that changes how you use the node.

A good sanity check once you've done all seven: run fundamentals_launch.py, then in a fresh terminal run rqt_graph (if installed) to see the topic/service/action connections you just built, rather than just reading logs.

Fundamentals

writing composable nodes (rclcpp_components), loading them via a component container (statically at launch or dynamically at runtime), and using this for performance-critical pipelines (e.g., camera driver → image processing in the same process).
