Executor

Overview

An executor in ROS 2 is the underlying engine responsible for coordinating and executing work (callbacks).

A node itself is just a passive holder of code. It cannot execute anything on its own. The Executor provides the actual CPU thread(s) to run that code. Whether composition is used or not, the default execution engine that ROS2 provides is the single threaded executor.

Functions of an executor

  • Monitors Events
    • It continuously checks the lower-level middleware (DDS) via a mechanism called a wait set to see if new topic messages have arrived, service requests have been made, or timers have expired.

  • Dispatches Callbacks
    • When an event occurs, the executor retrieves the event data and invokes the appropriate C++ callback function. E.g., timer or topic-subscription callback.

  • Enforces Execution Rules
    • It respects callback groups (such as `MutuallyExclusive` or `Reentrant`) to determine whether callbacks can run simultaneously in parallel or must wait their turn.

Types of Executors

  • SingleThreadedExecutor
    • Uses one single CPU thread to handle all registered nodes and callbacks sequentially. If one callback takes a long time, all other callbacks across all nodes assigned to this executor must wait.

  • MultiThreadedExecutor
    • Spawns a pool of worker threads. Free threads can pick up and execute callbacks in parallel across different nodes or within the same node, depending on its callback group settings.
