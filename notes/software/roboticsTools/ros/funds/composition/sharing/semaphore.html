Semaphore

Overview

std::counting_semaphore or std::binary_semaphore (C++20): Useful for controlling access when a fixed number of concurrent resource allocations are allowed or for signaling across callback threads.

Code

Deadlock, solution.

Here's a clear before/after that shows why std::counting_semaphore exists: it lets you cap how many threads can access a limited resource concurrently — something a plain mutex or atomic counter can't enforce on its own (they can track concurrency, but nothing stops more threads from proceeding at once). Both examples spin up 10 threads competing for a "resource pool" that should only allow 3 concurrent users at a time.

without_semaphore.cpp — all 10 threads rush in immediately. The final line prints something like Max concurrent 'connections' used: 10, even though the "pool" was only meant to allow 3. Nothing in the code actually stops threads from proceeding; the atomic counter just measures the overcrowding, it doesn't prevent it. with_semaphore.cpp — resourcePool.acquire() blocks a thread until a slot frees up, and release() hands that slot to the next waiter. The output ends with Max concurrent 'connections' used: 3, guaranteed, no matter how many threads you throw at it. That's the core value of std::counting_semaphore: it's a lightweight, purpose-built primitive for "let up to N things happen at once" — bounding resource pools, connection limits, producer/consumer buffers, etc.
