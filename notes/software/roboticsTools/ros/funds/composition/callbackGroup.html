Callback group

Background

A callback group is an execution control mechanism that tells the executor which callback functions can run concurrently and which ones must wait their turn.

Without callback groups, an executor treats a node as a single unit of execution. If one callback takes a long time to complete, it can block all other tasks in that same node like timers, subscription messages, or service calls—from running.

Types

When a callback (for a topic subscription, timer, service, etc.) is created, it is assigned to one of two group types.

Mutually exclusive

Only one callback in this group can run at a time.

Usecase

Protects shared data or hardware resources. For example, if you have a callback that writes directly to a motor driver, you never want two instances of it running simultaneously, or they might write conflicting motor commands.

Reentrant

Multiple callbacks in this group can run simultaneously in parallel, provided the executor has multiple threads to run them.

Usecase

Independent or read-only tasks. If you have a service that calculates mathematical transforms or processes images without modifying shared global variables, it can safely run in parallel.

Why Callback Groups Matter

Even MultiThreadedExecutor is used, ROS 2 defaults every callback to a mutually exclusive group scoped to the specific node.

This means that simply using a MultiThreadedExecutor will not allow two timer callbacks or two message callbacks on the same node to run at the same time unless the callbacks are explicitly assigned to a reentrant callback group or split across different MutuallyExclusive groups.
