Controller manager (CM)

Description

CM is the primary ROS node that handles the lifecycle (e.g. loads, activates, deactivates, unloads) of controllers and coordinates with the HAL (sensors or actuators).

When ros2_control is launched, a URDF's content is passed to CM as a string parameter called robot_description.

CM starts different controllers and binds specified hardware interfaces to them.

Component Parser

Inside CM (specifically in its on_configure or initialization phase), it passes robot_description to a class called ComponentParser (found in the hardware_interface package). The parser hunts for ros2_control XML tags. It iterates through every hardware block and extracts the plugin name and the component type.

Resource Manager

The parser passes the plugin names to another class within CM called the ResourceManager.

Resource manager is responsible for dynamically loading and initialising hardware resource plugins and managing the lifecycle of hardware interfaces to components defined in a URDF file. It uses pluginlib to find the compiled .so libraries corresponding to the names and gets back corresponding class instances.

In other words, hardware components are loaded as plugins (using pluginlib). They are not independent processes or nodes; they are shared libraries linked into CM at runtime.
